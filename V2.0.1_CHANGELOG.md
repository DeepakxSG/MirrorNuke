# MirrorNuke 2.0.1 — Essential video-path fixes

This patch is based on the latest `MirrorNuke-main.zip` supplied for testing. The existing advanced dashboard, room device directory, multi-display controls, live WebRTC statistics, audio path and remote navigation controls are retained.

## Fixes

- **Do not drop streamless WebRTC tracks.** The Windows receiver previously returned immediately when `RTCTrackEvent.streams` was empty. Streamless tracks are valid under Unified Plan. The receiver now attaches such tracks to a synthetic stream so `RTCVideoRenderer` can display them.
- **Receive-event fallback.** The viewer also handles `onAddTrack` / `onAddStream`, and periodically checks peer-connection receivers when a video track event was missed.
- **Prefer video streams.** The renderer now selects a stream containing a video track instead of accidentally selecting an audio-only stream.
- **First-frame feedback.** The viewer records the renderer's first-frame event and shows a diagnostic banner while video has not started rendering.
- **Android capture startup acknowledgement.** Android now confirms that the media-projection foreground service actually reached `startForeground()` before Flutter proceeds to `getDisplayMedia()`. The capture flow preserves the required order: user consent, foreground service, then projection capture.
- **Capture validation and logs.** Android capture checks that a video track was returned and records the track ID in the diagnostic log.
- **Version increment.** Flutter package version updated to `2.0.1+2`.

## What remains unverified

The code was inspected and static checks are included in the pack, but this environment does not have Flutter/Dart or the Android/Windows native build toolchains. A real Android phone + Windows PC test is still required to confirm that the device-specific projection pipeline produces frames.
