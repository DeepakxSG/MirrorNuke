# MirrorNuke 2.0.4 — Remote video and startup experience

## Fixed: remote video attachment
- Removed attempts to call `MediaStream.addTrack()` with tracks received from a remote WebRTC peer.
- Reuses stream objects supplied by `RTCTrackEvent.streams`, legacy `onAddTrack`/`onAddStream`, and `RTCPeerConnection.getRemoteStreams()`.
- If a streamless track has no remote stream mapped yet, the viewer reports that state and keeps checking for the actual remote stream; it does not manufacture a local stream.
- Keeps receiver recovery and first-frame diagnostics.

## Improved: Windows startup feedback
- Calls `runApp()` immediately after Flutter binding initialization instead of waiting for settings storage first.
- Adds a branded startup screen with real stages: preparing startup integration, loading saved preferences, and opening the dashboard.
- Adds an error/retry state if startup settings fail to initialize.
- Sets the generated Windows native title bar to `MirrorNuke` rather than `mirrornuke_app`.
- Loads SharedPreferences and secure-storage credentials concurrently to reduce initialization wait.
- The embedded signaling server continues initializing after the dashboard is shown; its ready/error state remains visible in the dashboard.

## Preserved
- Existing remote navigation controls.
- Local preview pinch-to-zoom and pan, zoom-aware pointer mapping, and immersive full-screen mode.
- Multi-monitor selection, connection metrics, device discovery, and existing GitHub Actions build jobs.

## Validation
Source-level checks and archive integrity are run when preparing this pack. Flutter analysis/builds and real Windows/Android/WebRTC testing must still be completed by GitHub Actions and on physical devices.
