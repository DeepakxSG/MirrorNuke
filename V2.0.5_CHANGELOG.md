# MirrorNuke 2.0.5: phone video fix (blank preview)

## Root cause
Android allows only ONE active screen-capture (MediaProjection) session. When the phone started sharing,
video capture started first, and then the phone-audio feature asked for a SECOND screen-capture
permission and created a second projection. Android's system service stops the existing projection when a
new one starts (MediaProjectionManagerService.startProjectionLocked -> stop(STOP_NEW_PROJECTION)).
The video capture was killed, but its WebRTC track stayed "live" and the data channel kept working, which
is exactly: controls work, "Video track connected, but no frames are rendering".
Telltale sign on the old build: the phone showed TWO screen-capture permission prompts when sharing started.

## Changes
- Android no longer starts the second projection (phone audio is off until it can share the video session).
  The toggle is disabled on Android and explains why. PC audio is unchanged.
- New "kick": a still phone screen produces no frames, so the viewer now asks the phone for a fresh frame
  every 1.5 s (up to 10 times) until the first frame renders. The phone shows a 2x2 pixel near-invisible
  overlay for 120 ms (needs the Accessibility service enabled).
- Version 2.0.5.

## Test
1. Rebuild BOTH Windows and Android from this source.
2. On the phone start sharing: you should see exactly ONE screen-capture prompt.
3. Connect from the PC with the phone on its home screen. Video should appear within a few seconds.

## Added after first test: controls and lag
- The phone now tells the PC whether it can perform touches. If the Accessibility service is off (or blocked by
  Android's "restricted settings" for sideloaded apps), the PC shows an orange banner explaining how to turn it on.
  Before, the buttons did nothing silently.
- Lag: phone screens were sent at full size (for example 1080x2400) with the "keep resolution, drop frames" rule,
  so a busy phone dropped to a low frame rate. Phones now send about 1.5x smaller frames (2.5x in Saver mode) and
  keep the frame rate up (MAINTAIN_FRAMERATE). Windows "Gaming" mode also keeps the frame rate up.
- The viewer's top bar shows resolution, fps, bitrate, round-trip time and packet loss. Use these to see whether
  lag comes from the phone (low fps) or the Wi-Fi (high RTT or loss).
