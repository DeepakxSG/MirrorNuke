# MirrorNuke 2.0.3 — CI null-safety and release workflow fix

## Fixed
- Fixed the Android and Windows `flutter analyze` failure caused by passing nullable `MediaStreamTrack.id` (`String?`) into a `Set<String>`.
- Added a stable attachment-key helper: use the WebRTC track ID when present, otherwise use object identity.
- Updated duplicate-track checks to avoid treating two missing IDs as the same track.
- Updated receiver-track recovery to use the same attachment key.
- Removed the unused direct `vector_math` import from `main.dart` and removed its redundant direct dependency from the generated Flutter pubspec template. Flutter's gestures library already supplies the `Matrix4` type used by the viewer.

## Build and CI
- Bumped Flutter package version to `2.0.3+4`.
- Updated the Inno Setup Windows installer version to `2.0.3`.
- Updated GitHub Actions to run on pull requests to `main`, restrict token permissions to `contents: read`, set job timeouts, clarify step names, and retain artifacts for 14 days.
- Kept `flutter analyze --no-fatal-infos` as a strict CI gate for warnings and errors; the workflow does not suppress analyzer failures.

## Validation limits
This source pack was checked for the changed Dart references, YAML structure, Python syntax, Node.js syntax, Android XML, and ZIP integrity. Flutter analysis, unit tests, APK compilation, Windows compilation, installer compilation, and device tests must run in GitHub Actions or on a machine with the required native toolchains.
